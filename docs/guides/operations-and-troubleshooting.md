# Operations and troubleshooting

> All recovery is explicit. Unknown writes are never auto-resent. Telemetry and remote error reporting remain disabled.

## Error-code recovery by area

### Imports

| Safe code / stage                                                                                              | Meaning                                                                                                                                   | Action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `unsupported_layout` at `parsing`                                                                              | Layout not recognized — no fixture-backed parser for this content.                                                                        | Try a supported layout (BDO image v1 via 2–10 ordered `statementPages`, ascending). Do not claim generic PDF/CSV support; add a new parser per `docs/guides/parser-authoring.md`.                                                                                                                                                                                                                                                                                                                                                                                              |
| `mime_signature_mismatch` / `unsupported_file_type` at `validated`                                             | Extension/MIME disagrees with magic bytes or type outside CSV/PDF/image.                                                                  | Use CSV (RFC-style, BOM tolerated), PDF, or JPG/PNG/WebP/TIFF/BMP with correct bytes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `empty_file` / `limit_exceeded` (`413`)                                                                        | Zero-byte or exceeds `MAX_FILE_SIZE_BYTES` (10 MiB statement, 5 MiB history) / `MAX_TOTAL_UPLOAD_BYTES` (30 MiB) / `MAX_PAGE_COUNT` (10). | Split the statement or reduce resolution; do not silently truncate.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `encrypted_pdf` at `validated`                                                                                 | PDF is password-protected/encrypted.                                                                                                      | Remove password locally before import; the service never uploads bytes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `history_schema_invalid` / `history_invalid_record` / `history_duplicate_record_id` / `history_limit_exceeded` | Wallet history CSV header/row/limit invalid.                                                                                              | Use a Wallet-native export (`account,category,currency,amount,ref_currency_amount,type,payment_type,note,date,transfer,payee,labels`) or the synthetic schema (`record_id,date,payee,description,amount,currency,category,account,source_row_id,note`). Comma and semicolon delimiters and a UTF-8 BOM are supported. Rows need an ISO date, PHP amount, and non-empty category; synthetic rows also need a unique ID. Fields are limited to 500 characters and imports to 10,000 rows. The entire import is rejected; a failed replacement leaves prior valid history intact. |
| `history_unsupported_currency` / `unsupported_currency`                                                        | Currency not `PHP`.                                                                                                                       | Statement and history must be `PHP` only; FX is not supported.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Provider connection

| Code                                                              | Meaning                                                   | Action                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `provider_not_configured` / `history_not_imported` at `validated` | Missing prerequisite for `POST /:id/categorize`.          | Import history and save/test a loopback provider before categorizing.                                                                                                                                                                           |
| `provider_malformed` at `validated`                               | Bad baseUrl.                                              | Base URL must be `http(s)` loopback `127.0.0.1/::1/localhost` (resolved & rechecked), no credentials/fragment/private/non-loopback/cloud host, no headers/tokens/proxy; length ≤500.                                                            |
| `provider_unavailable` / `provider_malformed` per proposal        | Local endpoint unreachable or returned non-schema output. | Proposal is `needs_review`; check `ollama serve` is running at the configured loopback URL, model is pulled, firewall allows loopback, retry **Test local connection** (health call uses no statement data). No statement data left the device. |
| `low_classification_confidence` / `unknown`                       | Confidence `<0.6` or explicit `unknown`.                  | Proposal is `needs_review`; use bounded rationale + up to 5 retrieved examples in Phase 3 review.                                                                                                                                               |

### Review

| Code                                                             | Meaning                                                                                                          | Action                                                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `review_not_initialized` / `review_not_found`                    | Review workspace not initialized or stale.                                                                       | Ensure extraction + history + proposals are current, then `POST /:id/review/initialize`. Replacing history or recategorizing invalidates review atomically.                                                                  |
| `category_required` / `category_not_allowed`                     | Approval requires a category exactly matching the active-session catalog; `unknown` never approvable.            | Pick a catalog category from the server-provided list. Replacing history changes the catalog and invalidates prior review decisions.                                                                                         |
| `split_total_mismatch` / `split_invalid` / `split_parent_locked` | Split children total does not equal source amount in centavos; parent container is not independently approvable. | Edit child amounts to exact signed total; centavo arithmetic only (use diagnostic helper `parsePhpAmountToMinorUnits`). At least two children; no nesting.                                                                   |
| `review_revision_conflict` (`409`)                               | Simultaneous tab/action; optimistic concurrency via `revision` / `reviewVersion`.                                | Refresh review (`GET /:id/review`), retry with fresh `revision`. Bulk approve requires `reviewVersion` and fails atomically if stale.                                                                                        |
| `reclassification_not_allowed` (`422`)                           | `POST /:id/review/:reviewItemId/reclassify` denied.                                                              | Allowed only for an unsplit source item that is `needs_review` or edited/flagged since last classification. Split children cannot be reclassified automatically. History/provider requirements mirror normal categorization. |
| `review_limit_exceeded` (`413`/`422`)                            | Bounded limits exceeded (response too large, audit cap 500).                                                     | Retry with smaller snapshot or clear to avoid unbounded history growth.                                                                                                                                                      |

### Wallet initial sync / rate limit / mixed results / unknown writes

| Scenario                                                                           | What you see                                                                                                                                                                                                                                                                               | What not to do                                                                    | Correct action                                                                                                                          |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Initial sync pending** (`409`)                                                   | `wallet_initial_sync_pending` with retry minutes; dry-run/commit halts.                                                                                                                                                                                                                    | Do not retry immediately in a loop.                                               | Wait the indicated minutes and retry explicitly.                                                                                        |
| **Rate limit** (`429`)                                                             | `wallet_rate_limited` with `Retry-After` (seconds) and bounded cancellable wait.                                                                                                                                                                                                           | Do not auto-retry.                                                                | Wait the bounded period or **Cancel**, then retry explicitly. No create occurs before confirmation.                                     |
| **Mixed** (`207`) / per-item results                                               | Batch summary plus per-`inputIndex` results: `succeeded` (Wallet ID present), `client_error` (non-retryable), `server_error_retryable`, `unknown` (timeout/malformed/index mismatch), `not_submitted`. Never call a batch successful merely because HTTP returned or some items succeeded. | Do not infer success.                                                             | Inspect each item’s status and safe error code; retry only via **Retry server errors** (server-selected `server_error_retryable` only). |
| **Unknown** (timeout, connection reset, invalid body, interruption after dispatch) | Affected chunk marked `unknown`.                                                                                                                                                                                                                                                           | **Never auto-resend.** Unknown writes are never automatically retried by the app. | Resolve manually outside the app (check Wallet), do not click retry for unknowns; unknowns are excluded from retry.                     |
| **Client error** (`400` class per item)                                            | Non-retryable; record will not succeed without user correction.                                                                                                                                                                                                                            | Do not retry.                                                                     | Fix source/category/account locally, create a fresh session/dry-run.                                                                    |
| **Server error retryable** (`500` class per item)                                  | Retryable via explicit per-item retry.                                                                                                                                                                                                                                                     | Do not retry successes or `unknown`/`not_submitted`.                              | Use **Retry server errors**; it submits only confirmed `server_error_retryable` rows.                                                   |
| **Not submitted**                                                                  | Later chunks after rate-limit/sync/halt remain `not_submitted`.                                                                                                                                                                                                                            | Do not assume they did not affect server state.                                   | They require a fresh dry-run — not implied by Retry.                                                                                    |
| **Stale snapshot** (`409 snapshot_stale`)                                          | Confirmation changed input (review/history/token/catalog/account/mapping/order/total/payload field).                                                                                                                                                                                       | Do not reuse snapshot.                                                            | Create a new dry-run after making changes.                                                                                              |

### Unknown writes are never auto-resent

A write timeout is `unknown`, never permission to resubmit. The journal retains known successes but invalidates pending snapshots; never silently discards a known success. Same-session retry selects only `server_error_retryable`; successes and unknowns are never resent.

### Common recovery drills

1. Import → `422 unsupported_layout` → verify you used ordered `statementPages` with 3 ascending synthetic images, or add a parser per guide.
2. Categorize → `422 history_not_imported` → re-import synthetic history, then test provider, then categorize.
3. Review approve → `409 review_revision_conflict` → refresh review, retry with new `revision`.
4. Wallet connect → `401 wallet_unauthorized` → verify token at `https://rest.budgetbakers.com/wallet/reference`, paste again (field is password-masked, never echoed).
5. Commit → `429 wallet_rate_limited` → wait `Retry-After`, retry is explicit only.
6. Results show `unknown` → check Wallet manually; do not press Retry for unknowns.

All diagnostics are explicit: `GET /:id/diagnostics/preview` (redacted, visible) and `GET /:id/diagnostics/download` (local JSON file, not persisted). Browser never writes `localStorage`/`sessionStorage`/`IndexedDB` with financial data.
